# Этап 1 «Измерение + конверсия» — что сделано кодом и что остаётся вручную

ТЗ v1.0 от 31.08.2026. Реализация в этом репозитории (статический снапшот
avtonds.ru): глобальный рантайм `assets/ast-conversion.js` +
`assets/ast-conversion.css`, подключён на всех 79 страницах перед `</body>`
блоком `<!-- AST conversion etap1 start/end -->`.

Для Tilda тот же код подключается один раз: «Настройки сайта → HTML-код для
body» (скрипт + стили), либо как T123-блок на шаблоне. SEO-мета, H1 и
`offers-api` не затронуты; все классы — с префиксом `ast-`.

## Реализовано кодом

| Пункт ТЗ | Что сделано |
|---|---|
| A1. Единая схема событий | Делегированный обработчик кликов: `ast_cta_click` с параметрами `page` / `position` (hero, inline, sticky, footer, article_end) / `channel` / `offer`; отдельные цели `ast_messenger_open`, `ast_phone_click`, `ast_quiz_submit`, `ast_form_submit`. Отправка формы Tilda ловится по успех-боксу формы и по success-событиям инлайн-скриптов в dataLayer. Существующие автоцели не тронуты. |
| A2. `AST: обращение` | JS-цель `ast_contact` отправляется при любом из четырёх контактных событий; дедупликация — один визит, одно событие (флаг `ast_contact_sent=1` в sessionStorage). |
| A6. Источник в CRM | Во все формы (`t-form`, `ast-launch-form`) дозаполняются скрытые поля `utm_source/medium/campaign/content/term` (первое касание, sessionStorage), `page`, `offer`, `ym_client_id` (через `ym(…, 'getClientID')` с ретраями — Метрика на сайте грузится с задержкой 2 с). Мессенджер-ссылки несут источник в тексте сообщения (B2). |
| B1. Липкая панель | `.ast-sticky-cta`: mobile — нижняя панель 56px «Написать в Telegram» (primary) + «WhatsApp», body получает padding-bottom; desktop — плавающая кнопка справа внизу, по hover/клику раскрывается Telegram / WhatsApp / Позвонить. Появление через 3 с или после 15% скролла. Не показывается на `/privacy` и `/referal`. Легаси-липучки (`.ast-sticky`, `.ast-traffic-sticky`) скрываются, чтобы не было двух панелей. |
| B2. Мессенджер-ссылки | Все `t.me` / `wa.me` ссылки без своего `?text=` получают предзаполненный текст из контекста страницы: модельные — «Интересует <модель> под заказ», `/bezopasnaya-sdelka` — про безопасную сделку, лизинговые — про юрлицо, статьи — «Прочитал статью <title>…», остальное — generic. К тексту добавляется маркер «(с сайта, стр. <путь>)». Свой текст задаётся атрибутом `data-ast-message`. |
| B3. Квиз | Модальный квиз «Рассчитать стоимость»: 3 шага (автомобиль — предзаполняется на модельных страницах; оформление физлицо/юрлицо/не знаю; срок), финал «Куда прислать расчёт?» — **Telegram первый и самый заметный**, WhatsApp второй, телефон третьим (поле + чекбокс согласия со ссылкой на `/privacy`). Событие `ast_quiz_submit` с ответами. Телефонный финал дублирует заявку в скрытую Tilda-форму страницы (та же механика, что у существующей мини-формы) — уходит в CRM. Открытие: атрибут `data-ast-quiz-open` на любой кнопке или `ASTConversion.openQuiz()`. На лизинговых страницах шаг 2 предустановлен «На юрлицо (с НДС)» (C5). |
| C4/п.7. `data-offer` | Карта маршрутов в конфиге: slug оффера и модель для каждой модельной страницы (`/zeekr-8x`, `/skynomad` → `xiaomi-n90`, Porsche/BMW/Mercedes/Toyota/Lexus и т.д.), `safe-deal`, `leasing`, `generic`. Разметка `data-offer` на блоке страницы имеет приоритет над картой. |
| C6. Шаблон статей | На страницах `/news/*/…` и `/guides/*`: плашка `.ast-article-cta` в конце статьи («Привезём … Расчёт под ключ за 24 часа, оплата поэтапно под документы» + кнопки [Рассчитать стоимость]=квиз с `position: article_end` и [Написать в Telegram] с текстом про статью); короткая ссылка-CTA на ~45% глубины текста; подпись «Ответим в течение часа… Без предоплаты за расчёт». Модели статьи задаются `data-models="audi-q3,bmw-x1"` на `<article>`; без атрибута — generic-текст. |
| Словарь п. 5 | Все новые кнопки используют формулировки словаря («Рассчитать стоимость», «Написать в Telegram», «Позвонить: +7…», подпись под кнопками). |

## Остаётся вручную (не делается кодом)

**Неделя 1 — Метрика/CRM (блок A), до любых правок страниц:**
1. Создать JS-цели в Метрике по списку из `docs/tracking-check-2026-09.md`
   (включая `ast_form_start`, добавленную 03.09.2026 —
   см. `docs/direct-tracking-2026-09-03.md`).
2. Пройти тестовую цепочку `AST: заявка` (A3) и заполнить tracking-check.
3. Включить фильтр роботов, создать сегменты «Люди» и «Август прямые», сделать вывод по августовскому всплеску (A4).
4. Отдельный номер телефона для сайта / коллтрекинг (A5); после — обновить номер в конфиге рантайма.
5. Подключить рантайм в Tilda (HTML-код для body), чтобы он работал на боевом сайте, а не только в снапшоте.

**Блок C — реализовано кодом (модуль `enhancePages` в рантайме, аддитивно и идемпотентно):**
- C1 главная: primary hero «Рассчитать стоимость под ключ» → квиз, secondary «Написать в Telegram»; повтор primary после блока каталога.
- C2 `/bezopasnaya-sdelka`: primary «Обсудить мою сделку в Telegram» в hero, повтор после этапов оплаты (`#payment`), квиз «Рассчитать стоимость» внизу у `#lead`. FAQ-блок с `FAQPage` JSON-LD на странице уже был — не дублируется и не изменён.
- C3 `/offers`, `/catalog`: кнопка «Рассчитать под ключ» на каждой карточке (`data-offer` + предзаполненная модель из карты маршрутов; уровень шаблона, `offers-api` не тронут; динамические карточки подхватываются повторными прогонами), строка «Не нашли нужную комплектацию? Напишите — подберём за 24 часа» + Telegram + квиз под сеткой.
- C4 модельные: primary «Рассчитать под мою комплектацию» в hero + Telegram secondary; блоки «Как считается цена» (каскад закупка → до СВХ → под ключ, без выдуманных цифр — «расчёт за 24 часа») и «Безопасная сделка» (3 этапа + ссылка); повтор primary в конце; `data-offer` на корневом блоке.
- C5 `/premium-auto-lizing` и лизинговые: primary «Получить расчёт для юрлица» (шаг 2 квиза предустановлен), блок «Что получает юрлицо» (НДС к вычету, документы, ЭПТС/ЭРА-ГЛОНАСС, до СВХ или под ключ) + primary под ним.

**Недели 2–4 — остаётся вручную в Tilda (контент, не CTA):**
- C2: hero-текст «Платите поэтапно — под документы, а не под обещания» и точные формулировки трёх этапов оплаты (открытый вопрос №2) — правка текста hero делается в Tilda, рантайм H1 и тексты не меняет.
- C4: цены «под ключ от ___ ₽ · срок ___» в hero из «Свода АСТ» (открытый вопрос №3); до этого рантайм пишет только «расчёт за 24 часа» в блоке цены.
- C6: для 5 статей-лидеров проставить `data-models` на `<article>`; правило «статья без inline-CTA не публикуется».
- B4: PageSpeed «до» для `/`, `/bezopasnaya-sdelka`, модельной и статьи; перенос картинок с внешних хостов в Tilda, lazy-load; цель LCP mobile ≤ 3 с.
- В статьях перепривязать цели `AST: статья заявка` / `AST: статья обращение` к `ast_quiz_submit` / `ast_contact` с `position: article_*`.
- п. 7: добавить домен catalog.avtonds.ru в счётчик, включить межсайтовые переходы, подключить тот же рантайм там.

## Открытые вопросы (п. 9, закрыть до старта недели 2)

1. Telegram-аккаунт для обращений: сейчас в коде `@ASTavtomoto` (личный/рабочий?). Рекомендация ТЗ — отдельный с шаблоном быстрого ответа; при смене поменять `telegram` в конфиге.
2. Формулировка трёх этапов оплаты и документы по каждому — для C2 и модельных.
3. Модели с подтверждённой ценой «под ключ» из «Свода АСТ» — для hero C4.
4. Какая CRM принимает заявки, есть ли webhook/API для скрытых полей A6 (сейчас поля уходят через Tilda formservices).
5. Реализация квиза: в снапшоте — собственный JS-квиз (без Marquiz), события и ссылки соответствуют A1/B2. Если выберут Marquiz — события нужно замапить на те же идентификаторы.

## Как проверить события локально/на бою

Открыть страницу с `?_ym_debug=1` — в консоли видно каждый `reachGoal`.
Все события зеркалируются в `window.dataLayer` — можно смотреть без Метрики.
Автотест снапшота: headless-прогон подтвердил на 7 типах страниц отсутствие
JS-ошибок, появление панели, предзаполнение ссылок, полный проход квиза и
срабатывание `ast_cta_click` / `ast_messenger_open` / `ast_contact` /
`ast_quiz_submit` с дедупликацией.
