# Отображение цен без НДС и с НДС

`assets/ast-conversion.js` дополняет карточки на главной, список `/offers` и страницу отдельного КП двумя строками цены. Исходная цена предложения сохраняется. Числа в USD и другие суммы без явно указанной налоговой базы не пересчитываются в российскую цену с НДС.

По состоянию на 09.09.2026 публичный `/api/public-offers` не передаёт налоговую базу. В таком случае обе строки показывают «Уточняется». Это отсутствие данных, а не нулевая цена или отсутствие НДС.

Рантайм использует уже загруженный `window.__astPublicOffersData` (`offers` или массив), не создаёт дополнительный запрос. Для будущей передачи проверенных налоговых данных предусмотрено необязательное поле предложения `taxPricing`:

```json
{
  "id": "example-only",
  "taxPricing": {
    "currency": "RUB",
    "vatRate": 22,
    "taxRegime": "standard",
    "netAmount": 10000000,
    "grossAmount": 12200000,
    "evidence": "document_confirmed"
  }
}
```

Это синтетический пример формата, не цена автомобиля. Поставщик данных должен передавать стоимость продажи в РФ с определённым составом поставки. `seller_claimed` означает «Заявлено продавцом», `document_confirmed` — «Подтверждено документами»; второе значение допустимо только после проверки документов. Клиентский код не проверяет документы самостоятельно.

Достаточно одной из двух сумм: вторая вычисляется и помечается «Расчёт от цены без НДС» или «Расчёт от цены с НДС». Обе суммы должны быть положительными числами. Расхождение двух переданных сумм со ставкой более чем на одну копейку, иная валюта/ставка/налоговый режим или отсутствие происхождения блокируют числовое отображение. Льготные, нулевые и маржинальные режимы требуют отдельного формата; автоматически трактовать их как стандартные нельзя. Суммы не являются обещанием налогового вычета.

Новые карточки, фильтрация и замена списка обрабатываются автоматически; поддержаны обе версии разметки витрины, включая `ast-pg-offer`. Этот контракт не добавляет отсутствующие данные на сервер: до наполнения источника строки останутся «Уточняется». Новая private-gallery витрина держит нормализованные предложения внутри своего замыкания и пока не передаёт `taxPricing`; для числовых цен её поставщик данных должен также выставлять проверенные исходные предложения в `window.__astPublicOffersData`. Фронтенд не делает отдельный дублирующий запрос и не обходит существующие фильтры актуальности: если витрина скрыла неподтверждённое КП, блок цены не возвращает его на страницу.

Проверка: `node scripts/verify-home-offers.mjs` (нужен пакет `playwright`, при отдельном расположении — `PLAYWRIGHT_MODULE`). Тесты используют синтетические предложения, перехватывают отправку форм локально и блокируют все внешние запросы.
