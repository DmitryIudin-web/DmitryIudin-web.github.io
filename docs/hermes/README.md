# Hermes для АСТ: единый комплект Windows и VPS

Обновлено 08.09.2026. Комплект продолжает существующую установку Hermes на Windows
и использует те же правила при установке нового профиля на Ubuntu/Debian.
Код находится в этом репозитории; приватный HERMES_HOME хранится отдельно.

Существующая установка обновлена с Hermes 0.17.0 до проверенной ревизии 0.21.1
по [порядку переключения с откатом](runtime-upgrade.md). Наличие процесса
не доказывает ответ модели, доставку сообщения или выполнение заданий.

## Что объединено

| Часть | Назначение |
|---|---|
| scripts/hermes/profile.py | Общий механизм применения, резервного копирования и проверки профиля |
| scripts/hermes/connect-existing.ps1 | Подключение существующего Windows-профиля без переустановки и перезапуска |
| scripts/hermes/bootstrap-vps.sh | Подготовка нового VPS и применение того же профиля |
| scripts/hermes/check-vps.sh | Проверка фактической конфигурации и runtime на сервере |
| scripts/hermes/verify-runtime.py | Проверка настоящего terminal handler в профиле без ключей |
| scripts/hermes/hermes-home/ | Общая политика, управляемый раздел SOUL и навык сайта |
| .github/workflows/hermes-kit.yml | Проверки на Windows, Ubuntu и Debian без настоящих токенов |

При подключении общего профиля сохраняются модель, провайдер, fallback, рабочий каталог,
распознавание речи и расписания. Файлы .env, auth.json, память, сессии и чужие навыки
не копируются и не меняются. В config.yaml объединяется только approvals; в SOUL.md
обновляется один помеченный раздел. Рядом создаётся ast-kit.json с путём рабочей
копии и устанавливается только навык ast/avtonds-site.

Перед изменением управляемых файлов создаётся приватная резервная копия в
HERMES_HOME/.ast-kit-backups/. На Linux права каталога 700, файлов 600;
на Windows новые управляемые файлы и резервные копии получают защищённый ACL
для текущего владельца и SYSTEM до записи содержимого. Права остальных файлов
существующего профиля требуют отдельной проверки. Ссылки и junctions в управляемых
путях и каталоге резервных копий отклоняются.
Повторное применение того же комплекта не создаёт новые копии и не меняет файлы.
Профиль внутри публикуемого репозитория запрещён.
Изменение прав после подключения обнаруживается проверкой и исправляется повторным
apply. На Linux файловая система должна реально исполнять chmod; общий Windows-диск
в WSL без metadata для приватного Linux-профиля не подходит.

## Существующая установка Windows

Откройте PowerShell в рабочей копии этого репозитория. По умолчанию используются
HERMES_HOME и уже установленный hermes из PATH. При нестандартном расположении
передайте -HermesHome и -RuntimeDir явно.

```powershell
# Предпросмотр: ничего не меняет.
.\scripts\hermes\connect-existing.ps1

# Подключить профиль, сохранить резервную копию, выполнить отдельную проверку.
.\scripts\hermes\connect-existing.ps1 -Apply
```

Обновляется существующий профиль. Скрипт не устанавливает второй runtime,
не запускает gateway, не меняет системные переменные пользователя и не отправляет
сообщения. Существующий сервис продолжает работу с прежним токеном.

**Совместимость:** версия 0.17.0 не исполняет approvals.deny, даже если YAML
сохранил эти ключи. После подключения такой профиль подготовлен к обновлению,
но проверка возвращает exit 2 и upgrade_required=true. Это не успешное включение
нового запрета публикации. Совместимость проверяется по реализации runtime,
а не только по строке версии, и показывается уже в предпросмотре. Допускается
проверенный набор SHA-256 исходников 0.21.1; неизвестная или изменённая реализация
требует отдельного review и обновления fingerprint после проверки.
Проверка исходников не заменяет проверку поведения.

Обновление активного runtime выполняется отдельным подготовленным действием:
проверить резервную копию, установить проверенную версию отдельно, остановить
старый gateway, переключить существующий сервис, проверить нового потребителя,
при ошибке вернуть прежний runtime. Одновременно два gateway с одним токеном
запускать нельзя. Команды обновления автоматически этот комплект не выполняет.

## Перенос на действующий VPS

Для сервера с работающими приложениями используйте отдельный
[порядок переноса с Windows, проверки и отката](windows-to-vps.md). Он учитывает
холодный снимок SQLite, отключение прежнего запуска, ограничение ресурсов и
доступа службы. Скрипт подготовки нового VPS этот перенос не выполняет.

## Новый VPS

Поддерживаемая цель: чистый Ubuntu 22.04/24.04 или Debian 12 с root-доступом и SSH.
Адрес сервера и запуск должны быть явно выбраны владельцем. Комплект сам ничего
не покупает и не выбирает сервер из сохранённых SSH-доступов.

До слияния PR комплект берётся именно из его ветки:

```bash
apt-get update && apt-get install -y git
git clone --branch claude/hermes-telegram-setup-3aeo3t --single-branch \
  https://github.com/DmitryIudin-web/DmitryIudin-web.github.io.git /opt/ast-hermes-kit
# Секреты вводите без помещения значений в историю команд и переписку:
read -rs -p 'Telegram token: ' TELEGRAM_BOT_TOKEN; echo
export TELEGRAM_BOT_TOKEN
read -r -p 'Allowed Telegram user IDs: ' TELEGRAM_ALLOWED_USERS
export TELEGRAM_ALLOWED_USERS
# Ключ выбранной модели задаётся тем же способом либо через мастер после установки.
bash /opt/ast-hermes-kit/scripts/hermes/bootstrap-vps.sh
```

SSH-порт определяется по текущему SSH_CONNECTION; при запуске вне SSH используется
22. Для другого порта задайте SSH_PORT явно. Несовпадение с текущим SSH-соединением
останавливает скрипт до изменения системы. Старые allow-правила UFW сохраняются;
проверка состояния требует активного UFW и действующего jail sshd в fail2ban.
Повторный запуск сохраняет существующую рабочую ветку сайта без автоматического pull.

Проверенный upstream зафиксирован на commit
6e2b8e070d28b1a3381a3fb290b6b8d6cce13cef (версия исходников 0.21.1).
Фиксируются и установщик, и устанавливаемая ревизия. Это не обещание автоматической
совместимости с будущим latest. Первое применение действительно обновляет активные
config.yaml и SOUL.md, созданные upstream, вместо записи неприменяемых .ast-template.
Повторный запуск сохраняет интеграции и не переустанавливает имеющийся runtime молча.

После успешной проверки профиля владелец выбирает модель и запускает сервис:

```bash
sudo -iu hermes
hermes model
hermes gateway start
hermes gateway status
```

Затем владелец отправляет новому боту обычное сообщение и голосовое.
Наличие процесса, результат doctor и успешный ответ API не заменяют этот тест.
Если на Windows уже работает тот же токен, сначала требуется подготовленное
переключение; для независимого пилота нужен другой бот.

## Полномочия и безопасность

Режим manual спрашивает владельца о распознанных опасных командах. Cron,
one-shot и unattended контексты получают deny. Дополнительно запрещены все
агентские git push и gh pr merge. Навык сайта заканчивается локальным commit
и передачей владельцу или уполномоченной задаче Codex. GitHub-токен с правами
публикации комплект не запрашивает и не импортирует.

Строковые запреты не являются полной изоляцией: другие программы, API, скрипты
и права ОС требуют своих ограничений. Перед выдачей агенту прав публикации
необходимы проверенные серверные ограничения GitHub для main. Настройка YAML
не является доказательством этих ограничений. CRM, деньги, реклама и сообщения
людям сохраняют отдельные правила разрешения.

Публичный статический сайт публикует служебные файлы тоже. robots.txt ограничивает
индексацию, но не доступ. Не сохраняйте здесь заполненные конфигурации, резервные
копии профиля, токены, пользовательскую память или журналы.

## Проверки и диагностика

```bash
python -m unittest discover -s scripts/hermes/tests -v
python scripts/sync_agent_docs.py --check
bash -n scripts/hermes/bootstrap-vps.sh
bash -n scripts/hermes/check-vps.sh
bash scripts/hermes/tests/test_vps_scripts.sh
shellcheck --severity=warning scripts/hermes/bootstrap-vps.sh scripts/hermes/check-vps.sh
```

Тесты используют временные профили и искусственные значения. Проверяются
сохранность существующих интеграций, первая/повторная установка настроек,
резервные копии и их ACL, запрет выхода через ссылки, откат при ошибке записи,
некорректный YAML, содержимое манифеста/SOUL/навыка, Windows-адаптер, варианты
команд публикации и несовместимый старый runtime. Bash-проверки используют
подставные команды для первой/повторной установки, SSH, UFW и кодов ошибок.

Полная установка ufw/fail2ban/systemd, переживание перезагрузки VPS, ответы
Telegram и распознавание реального аудио требуют проверки на выбранном сервере.
Проверки CI не являются доказательством такого развёртывания.

Общий инструмент требует PyYAML из окружения Hermes. Не запускайте его случайным
системным Python без этой зависимости. Проверка профиля:

```bash
/path/to/hermes/venv/bin/python scripts/hermes/profile.py check \
  --home /private/hermes-home --runtime /path/to/hermes
```

Exit 0 означает прохождение перечисленных проверок профиля и возможностей исходников;
exit 2 — профиль или runtime пока не готовы; exit 1 — ошибка чтения/применения.
Никакие значения ключей и содержимое переписки в отчёт не выводятся.

Поведенческая проверка установленного runtime:

```powershell
python scripts/hermes/verify-runtime.py --runtime D:\path\to\hermes-agent
```

Она создаёт временный профиль без настоящих ключей и проверяет настоящий
обработчик terminal: обычный echo исполняется, образцы push/merge блокируются,
session yolo и лишний аргумент force от модели не обходят deny. Сам тест
использует только безвредную печать текста. Для временных файлов на нужном диске
задайте TEMP/TMP перед запуском. Прямой внутренний Python-вызов с force=True
остаётся за пределами этой защиты; результат явно показывает это ограничение.

Проверено 08.09.2026: Windows — 27 тестов прошли, один POSIX-тест пропущен;
Linux — 24 прошли, четыре Windows-теста пропущены. Bash-сценарии, ShellCheck,
синхронизация AGENTS/CLAUDE и sitemap (58 URL, валидный XML) прошли.
Существующий Windows-профиль подключён с резервной копией; приватные данные
и настройки вне approvals сохранены, навык avtonds-site виден как enabled
в Hermes CLI. Процесс gateway при первом применении не менялся. Затем по отдельной
команде продолжения установлен runtime 0.21.1 и выполнено переключение с приватной
холодной копией для отката: профиль проходит проверку, Telegram подключён, пауза
снята. Встроенные upstream-навыки обновились; личные навыки и управляемый навык
сайта сохранены. Текстовый ответ на Windows владелец подтвердил. По отдельной
команде профиль перенесён на действующий VPS: Telegram подключён, включён
автозапуск systemd, проверены ключевой SSH, firewall и ограничения службы.
Подтверждение доставки и распознавания голоса владельца ведётся отдельно;
приватные результаты переноса в публичный репозиторий не помещаются.
