## 2. Что такое Hermes (коротко, по вебинару и докам)

Открытый агент-«обвязка» вокруг любой LLM, который живёт на сервере и общается с
вами через Telegram (текст, голосовые, файлы). Отличия от Claude Code, ради
которых его ставят:

- ставится **цель**, а не задача: агент сам делит её на шаги, запускает
  субагентов и работает долго, пока не докажет результат;
- сам **пишет себе скиллы** из повторяющихся задач и чинит их при ошибках;
- **память** о вас и ваших правилах, которую сам сжимает; поиск по прошлым сессиям;
- **любые модели**: Kimi, Codex по подписке ChatGPT, OpenRouter, Anthropic по
  API-ключу; дешёвая модель на служебные задачи;
- встроенные **кроны** с доставкой результата в Telegram, вебхуки, MCP, плагины;
- **опасные действия подтверждает в Telegram**, есть жёсткие запреты.

Ведущий вебинара настаивает: не ставить на свой компьютер (агент имеет доступ ко
всему и уязвим к промпт-инъекциям из писем и страниц), а брать отдельный VPS.

## 4. Решения по архитектуре

- **Отдельный VPS**, не рабочий ПК. Страна: если модели — Codex/Anthropic/
  OpenRouter, берите Нидерланды или Германию (ведущий: с российского IP они не
  работают). Если только Kimi — подойдёт и российский хостинг, тогда агент
  видит сайты, пускающие только с RU-адресов.
- **Размер** (по вебинару, цены не проверял): минимум 2 vCPU / 4 ГБ / 40 ГБ SSD,
  ~1000 ₽/мес; комфортно 4–8 vCPU / 16 ГБ, ~3000 ₽/мес. Локальный Whisper
  `small` работает на минимуме, `large-v3` — от 16 ГБ.
- **Пользователь `hermes` без sudo**, порты наружу только SSH, веб-панель через
  SSH-туннель. Агент не имеет доступа к вашему компьютеру, паролям и кошелькам.
- **Модель**: ведущий советует Kimi (дёшево, по подписке, не капризничает) или
  подписку ChatGPT/Codex. Про Claude — честно из документации Hermes:
  OAuth-вход работает **только на Claude Max с докупленными extra-usage
  кредитами** и тратит именно их; Claude Pro так подключить нельзя, только
  `ANTHROPIC_API_KEY` с оплатой за токены. «Шлюз подписки», о котором говорил
  ведущий, — обход правил Anthropic, в комплект не включён.
- **Рабочий каталог** агента — клон этого репозитория: он подхватывает
  `AGENTS.md` с правилами сайта, а `approvals.deny` не даст запушить в `main`.

## 5. Пошаговый запуск

### Подготовить (10 минут, только вы)

1. **Бот**: Telegram → @BotFather → `/newbot` → имя и username вида
   `ast_hermes_bot` → сохранить токен. Для старого бота из PR #4 — `/token`.
   Никому не пересылать; утёк — `/revoke`.
2. **Ваш ID**: написать @userinfobot, получить число. Это единственный
   пользователь, которому бот будет отвечать.
3. **Модель**: один из вариантов — ключ Kimi (platform.moonshot.ai → Console →
   API keys), ключ OpenRouter, ключ Anthropic, либо аккаунт ChatGPT для входа по
   подписке в мастере.
4. **VPS**: Ubuntu 22.04/24.04 или Debian 12, root по SSH-ключу. Варианты из
   вебинара: Hetzner (дешевле всего, нужен KYC и зарубежная карта), Hostinger
   (у них, по словам ведущего, есть готовый образ с Hermes в один клик),
   Timeweb Cloud, Selectel (серверы в Нидерландах с российской карты).

### Вариант А — скриптом по SSH (20 минут)

```bash
ssh root@СЕРВЕР
apt-get update && apt-get install -y git
git clone --depth 1 https://github.com/DmitryIudin-web/DmitryIudin-web.github.io.git /tmp/site
export TELEGRAM_BOT_TOKEN='...'          # из BotFather
export TELEGRAM_ALLOWED_USERS='...'      # ваш числовой ID
export KIMI_API_KEY='...'                # или OPENROUTER_API_KEY / ANTHROPIC_API_KEY
bash /tmp/site/scripts/hermes/bootstrap-vps.sh
```

Дальше, как напишет скрипт:

```bash
sudo -iu hermes
hermes model            # выбрать провайдера и модель (Kimi / Codex по подписке / OpenRouter)
hermes gateway start
hermes gateway status
journalctl --user -u hermes-gateway -f
```

Написать боту «привет». Потом голосовое — должна прийти расшифровка и ответ.
Команды в чате: `/new` — новая сессия, `/model` — сменить модель, `/help`.

### Вариант Б — готовый образ у хостера

Если хостер разворачивает Hermes сам (Hostinger по вебинару), после входа
в веб-панель всё равно примените наш комплект: зайдите по SSH, склонируйте
репозиторий и скопируйте `scripts/hermes/hermes-home/` поверх `~/.hermes/`
(`SOUL.md`, `config.yaml`, `skills/`), затем `hermes config migrate` и
`hermes gateway restart`. Проверьте, что в `~/.hermes/.env` есть
`TELEGRAM_ALLOWED_USERS` — без него бот ответит любому.

### Вариант В — отдать серверу Claude Code

Скопировать промпт из `docs/hermes/claude-code-prompt.md` в Claude Code Desktop
(или Codex) на своём компьютере. Он сделает вариант А сам, включая security
review сервера.

### Hermes Desktop на ноутбуке

Как на вебинаре: приложение с сайта Hermes, в настройках **Gateways → Add →
Remote gateway** или **SSH**. На сервере для этого должен работать
`hermes serve` (отдельный от шлюза процесс). Проще всего: SSH-подключение из
Desktop либо туннель `ssh -L 9119:127.0.0.1:9119 root@СЕРВЕР` и открыть
`http://127.0.0.1:9119`. Наружу панель не открывать.

## 6. Первые кроны (после того как бот отвечает)

Те же задачи, что сейчас делают облачные роутины, но с доставкой в Telegram.
Выполнять от пользователя `hermes`:

```bash
hermes cron create "0 8 * * 1-5" \
  "Утренняя сводка по АСТ: новые заявки и письма, статус PR в репозитории сайта, что сломалось за ночь. Коротко, списком." \
  --name "Утренняя сводка" --deliver telegram

hermes cron create "0 10 * * 1" \
  "Проверь новости по маркам из каталога avtonds.ru за неделю и предложи 3 темы для страниц news/. Ничего не публикуй." \
  --name "Темы новостей" --deliver telegram --skill avtonds-site
```

Модель для всех кронов лучше закрепить один раз:
`hermes config set cron.model_provider kimi-coding` и `hermes config set cron.model <модель>`
(иначе крон снимает копию текущей модели и при её смене останавливается с
предупреждением — так устроена защита от неожиданных расходов).

## 7. Безопасность: чек-лист

- [ ] Root-пароль от хостера сменён, вход по паролю выключен, только SSH-ключ.
- [ ] `ufw status`: открыт только SSH. Порты 8642 (API) и 9119 (панель) закрыты.
- [ ] `TELEGRAM_ALLOWED_USERS` задан; `TELEGRAM_ALLOW_ALL_USERS` отсутствует.
- [ ] `~/.hermes/.env` с правами 600, в чат и в git не попадает.
- [ ] `approvals.mode: smart`, `cron_mode: deny`, deny-список на месте (`hermes config get approvals.deny`).
- [ ] Пользователь `hermes` без sudo. Криптокошельков, паролей и клиентской базы на сервере нет.
- [ ] Обновления: `hermes update` раз в неделю (можно кроном), `hermes doctor` после.

## 8. Частые проблемы

| Симптом | Что делать |
|---|---|
| `hermes: command not found` после установки | `source ~/.bashrc` или `~/.local/bin/hermes` |
| Бот молчит | `hermes gateway status`, журнал; проверить, что тот же токен не запущен ещё где-то |
| Бот отвечает «unauthorized» | ID в `TELEGRAM_ALLOWED_USERS` не ваш; уточнить у @userinfobot |
| Голосовые не распознаются | `pip install faster-whisper` в venv Hermes уже сделан скриптом; на слабом сервере поставить `stt.local.model: base` или `stt.provider: groq` |
| «API key not set» | `hermes model` или `hermes config set KIMI_API_KEY ...` |
| Крон остановился после смены модели | закрепить `cron.model`/`cron.model_provider`, см. раздел 6 |
| Установщик не проходит с VPN/RU-IP | взять сервер вне РФ или использовать Kimi (`kimi-coding`) |
