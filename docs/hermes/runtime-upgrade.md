# Обновление существующего Windows runtime

Продолжение PR №28 от 08.09.2026. Цель: заменить установленный Hermes 0.17.0 на проверенную ревизию 0.21.1, сохранить личный профиль и единственный Telegram gateway. Команда пользователя «Продолжай» относится к этому подготовленному этапу.

## Выбранный способ

Новый runtime и отдельное окружение Python размещаются рядом со старым, вне публичного репозитория. Используется commit `6e2b8e070d28b1a3381a3fb290b6b8d6cce13cef`, существующий Python 3.11 и `uv sync --frozen --no-dev --extra messaging --extra voice`. Каталоги кэша и временных файлов задаются на диске рабочих данных. Старое окружение не изменяется.

Это позволяет проверить зависимости до остановки шлюза и вернуть прежний runtime. Обновление поверх существующего окружения усложнило бы откат; второй активный gateway с тем же токеном создал бы конфликт Telegram. Ни один из этих вариантов не нужен.

## Проверяемый порядок

1. Проверить Git, текущий PID, владельца процесса, автозапуск и расположение профиля. Профиль и его резервные копии должны находиться вне публикуемого сайта.
2. Установить отдельный runtime по зафиксированному lock-файлу. Временный профиль без настоящих ключей используется для `verify-runtime.py`: обычная команда исполняется, запрещённые образцы блокируются настоящим обработчиком terminal. Даже при неисправном запрете образцы лишь печатают текст и не публикуют данные.
3. Проверить отсутствие ссылок, junction и hardlink внутри профиля. Сохранить снимок ACL в приватном каталоге, затем ограничить доступ: полный доступ только текущему владельцу запуска и SYSTEM. Содержимое файлов при этом не меняется. Учётная запись автозапуска должна совпадать с выбранным владельцем. Если старый служебный файл доступен для замены, но его ACL создан администратором и недоступен для изменения, после остановки допускается атомарно пересоздать его с тем же содержимым и приватными правами текущего пользователя; пустые служебные каталоги пересоздаются только после проверки пустоты. Повышение привилегий не требуется.
4. Остановить старый gateway штатной командой старого runtime. Проверить отсутствие прежнего процесса; не использовать `--replace` и не запускать второй потребитель. После остановки сохранить холодную приватную копию профиля, включая базы и возможные WAL/SHM. Из копии исключаются только кэши, исполняемые инструменты, временные блокировки и предыдущие резервные копии.
5. Выполнить новым runtime `hermes pause --reason runtime-upgrade`: маркер ESTOP приостанавливает новые turns и автоматические задания. Перевести существующий автозапуск и путь CLI на новый runtime, сохранив прежние настройки запуска для отката. Использовать скрытый запуск Windows через созданный upstream VBS. Если существующая Scheduled Task недоступна для редактирования, её прежний CMD-вход может вызывать этот VBS; не создавать второй автозапуск. Однократно запустить именно существующую задачу через `Start-ScheduledTask` и дождаться нового PID. `hermes gateway start` в 0.21.1 использует отдельный direct spawn и сам по себе не проверяет Scheduled Task.
6. Сверить конфигурацию, SOUL, ключи, память и пользовательские навыки с копией. База сессий может штатно изменить схему: её сохранность проверять по содержательным счётчикам и целостности, а не по равенству хэшей. Не выводить переписку или секреты в отчёт.
7. При неуспешном старте остановить новый процесс, восстановить холодную копию изменённых файлов и прежний запуск, затем отдельно проверить старый gateway. Никогда не запускать 0.17 поверх мигрированной базы без восстановления.
8. После приёмки выполнить `hermes resume` и отдельным чтением подтвердить отсутствие ESTOP, живой процесс и подключённую платформу. Пауза исключает выполнение cron во время проверки и повторную доставку после rollback. Сохранённый пользовательский PATH действует в новых терминалах; уже открытые процессы используют прежнее окружение.

## Критерии приёмки и ограничения

- Новый runtime использует проверенный исходный код; зависимости установлены из lock-файла. Общий профиль проходит `profile.py check`.
- Проверка поведения проходит через настоящий обработчик инструмента, без LLM, токенов или отправки сообщений. Лишний аргумент `force` от модели не должен обходить deny.
- Один рабочий gateway, сохранённые данные, закрытые ACL и приватный путь отката подтверждены отдельным чтением после изменений.
- Прямой внутренний Python-вызов `terminal_tool(force=True)` в этой версии обходит проверки. Этот параметр не передаётся обработчиком инструмента модели. Это ограничение доверенного кода, а не доказательство полной изоляции: произвольный Python, другие инструменты и API требуют самостоятельного контроля полномочий. Агенту не выдаётся новый GitHub-токен.
- `gateway start` не выполняет явную миграцию config.yaml, но открытие SessionDB обновляет схему базы. Перед первым запуском обязательна холодная копия. На этом этапе не выполнять `config migrate` и `doctor --fix`: они меняют дополнительные настройки и могут переписать .env/SOUL. Обновление встроенных навыков при старте штатно; персональные изменения и навык сайта проверяются отдельно.
- Ответ владельцу в Telegram и распознавание его голосового сообщения требуют отдельного пользовательского сообщения. Подключение платформы само по себе не доказывает эти сценарии.
- Merge в main, публикация сайта, перенос на VPS и покупка ресурсов в этот этап не входят.

Риски повторного запуска: устаревший автозапуск, конкурентное изменение профиля, запуск старой версии с новой базой, вновь созданные файлы с широкими ACL. Проверки после переключения должны охватывать эти случаи. Инструкции подключения профиля остаются применимыми к существующей установке; сам коннектор не обновляет runtime автоматически.
