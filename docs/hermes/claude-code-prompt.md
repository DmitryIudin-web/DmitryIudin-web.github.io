# Промпт для Claude Code Desktop / Codex: развернуть Hermes на арендованном сервере

Это тот самый вариант из вебинара: вы берёте VPS, отдаёте своему локальному
Claude Code (или Codex) доступ к серверу, и он ставит и настраивает Hermes сам.
Скопируйте текст ниже целиком, подставьте свои значения в `<...>` и отправьте
в новый чат Claude Code на своём компьютере (не в облачную сессию — ей нужен
ваш SSH-ключ и доступ к серверу).

Пароль root и токены в чат **не вставляйте** — Claude Code возьмёт их из
переменных окружения или спросит по ходу, а в `.env` на сервере они попадут
без вывода на экран.

---

```text
Разверни Hermes Agent на моём новом VPS и подключи к нему Telegram-бота.

Сервер: ssh root@<IP_СЕРВЕРА> (порт <22>), вход по SSH-ключу <~/.ssh/id_ed25519>.
Если ключа на сервере ещё нет — сначала добавь его через ssh-copy-id, я введу
пароль сам, а потом отключи вход по паролю (PasswordAuthentication no).

Готовый комплект для этого сервера лежит в репозитории
https://github.com/DmitryIudin-web/DmitryIudin-web.github.io в каталоге
scripts/hermes/ — прочитай docs/hermes/README.md и делай по нему:

1. Склонируй репозиторий на сервер во временный каталог и запусти
   scripts/hermes/bootstrap-vps.sh от root. Перед запуском экспортируй
   переменные (спроси у меня значения по одному, не печатай их в ответах):
   TELEGRAM_BOT_TOKEN, TELEGRAM_ALLOWED_USERS=<мой числовой Telegram ID>,
   и ключ модели: KIMI_API_KEY (или OPENROUTER_API_KEY / ANTHROPIC_API_KEY).
   Если я скажу, что буду входить по подписке ChatGPT/Codex — ключ не нужен,
   вместо него потом пройдём hermes model → "ChatGPT or Codex Subscription".
2. После скрипта войди как пользователь hermes (sudo -iu hermes), выполни
   hermes model и выбери провайдера и модель, которые я назову.
3. Запусти шлюз: hermes gateway start, проверь hermes gateway status и
   journalctl --user -u hermes-gateway -n 50. Бот должен ответить мне в
   Telegram на сообщение "привет" — я напишу его сам и скажу, что вижу.
4. Проверь голосовые: я отправлю голосовое, бот должен вернуть расшифровку
   и ответ. Если faster-whisper не тянет сервер — переключи stt.provider на
   groq и попроси у меня GROQ_API_KEY.
5. Проведи security review сервера: ufw пропускает только SSH; порты 8642 и
   9119 наружу не открыты; вход по паролю отключён; root-пароль, который
   прислал хостер, сменён (сгенерируй новый, покажи один раз, я сохраню);
   fail2ban активен; у пользователя hermes нет sudo; ~/.hermes/.env с
   правами 600. Выведи результат таблицей.
6. В конце запусти scripts/hermes/check-vps.sh и пришли его вывод.

Правила: ничего не публикуй в main репозитория сайта; секреты не выводи в
чат и не сохраняй в файлы кроме ~/.hermes/.env на сервере; если что-то
падает — сначала покажи ошибку и предложи вариант, потом чини.
```

## Что подготовить до запуска промпта

| Что | Где взять | Куда пойдёт |
|---|---|---|
| IP и root-доступ к VPS | письмо хостера после оплаты | SSH |
| Токен бота | Telegram → @BotFather → `/newbot` (или `/token` для существующего) | `TELEGRAM_BOT_TOKEN` |
| Ваш числовой ID | Telegram → @userinfobot | `TELEGRAM_ALLOWED_USERS` |
| Ключ модели или подписка | platform.moonshot.ai (Kimi), openrouter.ai, console.anthropic.com, либо аккаунт ChatGPT | `.env` или OAuth в `hermes model` |

Бот для Hermes должен быть **отдельным**: один токен может опрашивать
Telegram только из одного процесса. Если тот же бот уже где-то запущен
(например, старый автопостинг в @ASTavtomoto), Hermes и он будут отбирать
друг у друга сообщения.
