# Объединение существующего Hermes и комплекта VPS

Дата: 08.09.2026. Основание: пользователь поручил объединить установленный Hermes и комплект из PR №28, продолжая этот PR.

## Результат и границы

Один набор правил и инструментов в `scripts/hermes/` обслуживает существующий профиль Windows и новый профиль Linux. Рабочие секреты, OAuth, сессии, память и задания остаются вне репозитория. Существующая установка не переустанавливается и её шлюз не перезапускается. Изменения публикуются только в ветке PR №28; merge в main и развёртывание на VPS не входят в эту работу.

Нынешний Windows-профиль уже использует ручное подтверждение, OpenRouter и локальное распознавание. Эти настройки и рабочий каталог при подключении сохраняются. Добавляются отсутствующие ограничения, навык сайта и управляемый раздел SOUL. Код комплекта размещён отдельной рабочей копией `control` рядом с существующим `runtime`, на ветке `claude/hermes-telegram-setup-3aeo3t`.

## Решение

Выбран общий Python-инструмент применения профиля и тонкие входы PowerShell/Bash. Это меньше изменений, чем перенос всего установленного runtime в публичный Git или создание второго независимого проекта. Копировать upstream Hermes, пользовательские данные и установочные кэши в PR не требуется.

Интерфейс: `profile.py apply --home PATH --workspace PATH --mode existing|new [--dry-run]`; `profile.py check --home PATH --runtime PATH`; `profile.py capabilities --runtime PATH`. YAML читается PyYAML из окружения установленного Hermes. Изменяемые файлы: config.yaml, управляемый раздел SOUL.md, один навык avtonds-site, локальный манифест ast-kit.json. Перед изменением существующих файлов сохраняется приватная резервная копия. Проверка не выводит значения ключей, модельные endpoint URL, журналы или переписку.

## Существенные случаи

Повторный запуск не должен менять модель, рабочие расписания или существующий персональный текст. Невалидная конфигурация и конфликт прав завершаются до применения. Резервные копии не попадают в Git. Существующие процессы могут читать профиль во время работы, поэтому запись производится атомарно. Тот же Telegram-токен нельзя запускать на двух опрашивающих gateway; перенос допускается только отдельным подготовленным шагом с остановкой старого потребителя и проверкой нового.

## Дальнейшее действие

Установленный runtime 0.17.0 не исполняет approvals.deny. Подключение общего профиля не устраняет это ограничение: config_ok может быть true при ok=false и upgrade_required=true. Следующий этап — подготовить обновление runtime с откатом и переключением единственного gateway, затем проверить ответ на запрос владельца и определить необходимость VPS. Пользовательское календарное время до готовности этого этапа не требуется. Покупка, перенос, новые токены и запуск второго сервиса не выполняются автоматически в рамках данного PR.
