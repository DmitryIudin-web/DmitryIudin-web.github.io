# Задание для Claude на вашем компьютере (Cowork)

Из облака эти шаги сделать нельзя: нужен браузер, где вы уже залогинены
в Яндекс Метрику, Tilda и CRM. Пароли никому передавать не нужно —
Claude работает прямо в вашем браузере, вы только подтверждаете действия.

**Как запустить:** откройте приложение Claude на компьютере, где открыты
Метрика и Tilda, и отправьте ему весь текст ниже (от разделителя и до конца).

---

Ты работаешь в моём браузере. Выполни настройку этапа 1 «Измерение +
конверсия» для сайта avtonds.ru. Счётчик Яндекс Метрики: **106049767**.

Код на стороне сайта готов и проверен: рантайм `assets/ast-conversion.js`
раздаётся с https://dmitryiudin-web.github.io и работает без ошибок.
Ждёт только целей в Метрике и подключения в Tilda.

## 1. Цели в Метрике

Открой https://metrika.yandex.ru → счётчик 106049767 → Настройки → Цели.
Создай цели типа **JavaScript-событие** (идентификатор — точно как указано,
регистр важен):

| Название цели | Идентификатор |
|---|---|
| AST: клик CTA | `ast_cta_click` |
| AST: мессенджер | `ast_messenger_open` |
| AST: клик телефон | `ast_phone_click` |
| AST: квиз | `ast_quiz_submit` |
| AST: форма | `ast_form_submit` |
| AST: обращение | `ast_contact` |

Цель «AST: обращение» — главная. Седьмую цель `ast_call` создавай только
если уже подключён коллтрекинг; иначе пропусти.

Существующие цели и автоцели НЕ удаляй и не меняй.

## 2. Подключение кода в Tilda

Открой https://tilda.cc → проект avtonds.ru → Настройки сайта → Ещё →
«HTML-код для вставки внутрь BODY» (в конец body). Вставь:

```html
<!-- AST conversion etap1 start -->
<link rel="stylesheet" href="https://dmitryiudin-web.github.io/assets/ast-conversion.css?v=20260903">
<script src="https://dmitryiudin-web.github.io/assets/ast-conversion.js?v=20260903" defer></script>
<!-- AST conversion etap1 end -->
```

Сохрани и нажми «Опубликовать все страницы».

Если такой блок там уже есть со старой датой в `?v=` — замени дату на
`20260903`, иначе у части посетителей останется закешированная версия
без починки квиза.

## 3. Проверка, что данные пошли

1. Открой https://avtonds.ru/?_ym_debug=1, открой консоль браузера.
   При клике по кнопке «Написать в Telegram» в консоли должны появиться
   `reachGoal` с `ast_cta_click`, `ast_messenger_open` и `ast_contact`.
2. Через час: Метрика → Отчёты → Конверсии — у целей должны быть
   ненулевые значения.

Если в консоли пусто — код в Tilda не подключился, вернись к шагу 2.

## 4. Сквозная проверка до CRM

Отправь тестовую заявку через форму: телефон `+7 900 000-00-01`, имя и
комментарий с пометкой «ТЕСТ». Проверь по цепочке:

- визит виден в Метрике (Отчёты → Конверсии → `ast_form_submit`);
- заявка пришла в CRM;
- в карточке есть `utm_source/medium/campaign`, `page`, `offer`,
  `ym_client_id`.

Повтори то же для квиза: открой «Рассчитать стоимость», дойди до финала,
выбери «Жду звонка с расчётом». В CRM у этой заявки должны быть
`scenario=quiz` и `source_detail=ast_quiz`.

Если цепочка рвётся — зафиксируй, где именно: Tilda webhook, скрипт цели
или CRM.

## 5. Фильтр роботов и сегменты

- Настройки счётчика → Фильтры → включи «Не учитывать роботов по строгим
  правилам и поведению».
- Сегмент **«Люди»**: Роботность = «Люди»; исключить визиты короче 5 секунд
  с одной страницей при источнике «Прямые заходы». Сохрани.
- Сегмент **«Август прямые»**: период 31.07–22.08.2026, источник
  «Прямые заходы». Посмотри по нему географию, устройства, отказы и
  2–3 записи Вебвизора. Напиши вывод: боты, рассылка или реальные люди.
  Контекст: ~1 300 прямых визитов за три недели при отказах 65%.

## 6. Секрет для Telegram-автопостинга

GitHub → репозиторий DmitryIudin-web/DmitryIudin-web.github.io →
Settings → Secrets and variables → Actions → New repository secret.
Имя: `TELEGRAM_BOT_TOKEN`, значение — токен бота канала @ASTavtomoto.
Без него автопостинг анонсов не работает.
